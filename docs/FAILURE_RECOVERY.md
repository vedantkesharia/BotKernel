# Simulator recovery
Migration 0002 adds bounded attempts and due times. The recovery process scans due actions, delaying newly reserved actions 30 seconds. It uses the same per-action session advisory lock as Kafka executors, held across effect and ledger transactions. Worker death releases the lock. Receipt inspection precedes retry-limit/deadline checks; a committed effect is finalized instead of repeated. No receipt plus expired deadline/exhausted attempts yields FAILED. Divergent or missing external state yields ESCALATED and retains reservation/quota. Backoff doubles from the configured base and caps at 300 seconds.

Malformed/unknown Kafka action IDs are recorded in dead_letters before committing their offsets. Publisher crash after acknowledgement retains the outbox row and can duplicate publication. Fault switches CRASH_AFTER_EFFECT and CRASH_AFTER_PUBLISH are test-only; disable them for recovery. SIMULATOR_FAILURE=permanent injects known rolled-back effects.

These guarantees depend on the simulator atomic receipt contract. There is no arbitrary external exactly-once claim. Unexpected infrastructure errors retain reservations and rely on restart/reconciliation. Escalated actions retain quota and require human diagnosis; this is not a general automated external-service compensation protocol.

Current migration tests cover fresh/repeated startup, valid legacy upgrade, incompatible legacy rejection, head-schema drift and preservation through revision `0009`. Authentication and admission are tested at the API boundary. Do not infer complete coverage of every broker, dead-letter or external-service failure from those tests.

The November 14 local fault matrix executed three receipt-before-finalization crashes with explicit duplicate delivery, one publisher crash after Kafka ACK/before publication commit, and one publisher pause/restart. All five logical actions reached SUCCEEDED with one receipt/effect/version increment each and zero unresolved actions. These are bounded process-failure tests, not machine-loss, broker-failover or disaster-recovery restore tests.
